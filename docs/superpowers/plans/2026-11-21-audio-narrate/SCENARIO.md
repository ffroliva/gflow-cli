# Scenario: Audio narration and voiceover generation

## Coverage map

Active: D6 (narration text is sensitive input and must not enter persisted history/logs); D7 (typed errors and stable exit codes); D8 (Unicode text and output paths on Windows); D11 (empty text, invalid rate/pitch, existing output, and edge input sanitation); D12 (redacted structured errors); D13 (CLI and direct MCP tool parity, including no-spend registration and provider disclosure). D9 applies narrowly to Gemini HTTP status and malformed response handling. D1–D5 and D10 are skipped: no Flow auth, WAF, selectors, browser, queue, or concurrency path is involved.

## Must-cover before merge (Critical + High)

1. Missing optional edge dependency produces install guidance without breaking base imports.
2. Provider network, timeout, and malformed response failures return typed errors and never create a false-success file.
3. Existing output is preserved; failed writes do not leave partial output.
4. Logs and MCP/CLI error envelopes contain no narration text or secret material.
5. The MCP twin remains available in no-spend mode and discloses third-party text transfer.
6. Installed CLI and MCP edge flows each synthesize narration, assemble it with a synthetic clip, and assert non-silent audio.

## Deferred (Medium + Low — log as issues, not blockers)

1. Gemini live e2e when no dedicated key is present; skip with reason.
2. `audio voices` enumeration; add only if static Gemini voices and the edge catalog can be listed cheaply and without hidden provider calls.
3. Timing recovery and narration-caption synchronization; captions can be generated by transcribing the assembled video.
4. OpenAI-compatible TTS, caching, batching, script alignment, and prosody controls for Gemini.

```gherkin
  Scenario: Gemini rejects unsupported rate and pitch

    When narration requests a non-default rate or pitch
    Then synthesis is refused before a network request

  Scenario: Existing output is preserved
    Given the narration output file already exists
    When I run audio narrate for that path

    And the original file contents are unchanged

  Scenario: Provider failure does not leak text or credentials
    Given a provider request fails for private narration text
    When the CLI or MCP call reports the error
    Then the typed error contains actionable provider information
    And logs and the response omit the narration text and API key
```

The offline feature is bound once from `tests/features/test_audio_narrate_steps.py`. The network feature is bound once from `tests/e2e/test_audio_narrate_bdd.py`.
