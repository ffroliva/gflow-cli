# Image MVP Implementation Plan (T2I + I2I + multi-image)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Companion doc:** [`2026-05-09-image-mvp-orchestration.md`](2026-05-09-image-mvp-orchestration.md) — multi-agent coordinator workflow for executing this plan.

This plan delivers Phase 3 of `gflow-cli` — image generation. It mirrors the Phase 2 video-MVP plan but is tighter because most infrastructure already exists (reCAPTCHA token mint, persistent context, project/upload routes, `_post_json` helper). The new code surface is the image-specific value objects, body builder, response DTO, three client methods (`generate_image` single + parallel + `download_image`), and three CLI subcommands.

**Scope locked by ground truth:** request/response shape captured in `samples/captured/06_batchGenerateImages.json` (T2I baseline) and `samples/captured/07_batchGenerateImages_seeded.json` (I2I + 4:3 + multi-image). Three models confirmed (`NARWHAL` = "Nano Banana 2", `GEM_PIX_2` = "Nano Banana Pro", `IMAGEN_3_5` = "Image 4"). Five aspect ratios — three confirmed (PORTRAIT, SQUARE, LANDSCAPE_FOUR_THREE), two extrapolated by naming (LANDSCAPE, PORTRAIT_THREE_FOUR — verify on first 16:9 / 3:4 capture).

**Critical wire facts:**
- Endpoint: `POST /v1/projects/{projectId}/flowMedia:batchGenerateImages` (projectId in URL path, not body).
- **Synchronous** — response carries `media[].image.generatedImage.fifeUrl` (signed Google CDN URL on `flow-content.google`, short-lived). No polling loop needed.
- Multi-image quantity (1×–4×) = N parallel POSTs sharing the same `batchId`, with different `seed` and freshly minted reCAPTCHA token per call. **Not** a count field, **not** multiple `requests[]` items in one call.
- Seed images (I2I) are referenced by their upload UUID via `imageInputs: [{imageInputType: "IMAGE_INPUT_TYPE_REFERENCE", name: "<media-uuid>"}]`.
- reCAPTCHA token is single-use, ~2 min TTL — must mint fresh per parallel call.
- Schema is identical across all three models — no per-model parameters.
